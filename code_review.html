1. GNN & Scenario Engine (Supply_wind.py, STGNN.py)

CRITICAL  Isolation scenario adjustment has a unit error

In run_scenario(), the cross-border flow features are zeroed to simulate isolation. The intent is to compensate by telling the model that domestic production must now fill the gap. But the adjustment is computed in inconsistent units:

lag1_std = x_std[0, 0, 0, PROD_LAG1_IDX].item()     # raw MW std  (~200 MW)

fi_import_delta = x_mod[:, :, 0, FLOW_FI_IDX].clone()  # ALREADY normalized (dimensionless)
x_mod[:, :, 0, PROD_LAG1_IDX] -= (fi_import_delta + lv_import_delta) / lag1_std

x_mod is X_test_t — already standardized. So fi_import_delta is in normalized units (order ~1). Dividing by lag1_std (~200 MW) makes the adjustment ~200× too small — essentially zero. The model barely perceives isolation.

Fix — de-normalize the flows first:

flow_fi_std = x_std[0, 0, 0, FLOW_FI_IDX].item()
flow_lv_std = x_std[0, 0, 0, FLOW_LV_IDX].item()
delta_mw = fi_import_delta * flow_fi_std + lv_import_delta * flow_lv_std  # back to MW
x_mod[:, :, 0, PROD_LAG1_IDX] -= delta_mw / lag1_std   # into normalized production units
Impact: If S2 (isolated) looks almost identical to S1 (full grid) in your results, this is why. The isolation signal is not reaching the model.

MODERATE  Learning rate too low, likely under-trained

optimizer = torch.optim.Adam(model.parameters(), lr=1e-5, weight_decay=1e-2)
EPOCHS = 50

lr=1e-5 is an order of magnitude below typical Adam defaults for GNNs (1e-3 to 1e-4). Combined with weight_decay=1e-2 (strong regularisation) and only 50 epochs, the model is likely under-converged. The 75% quantile coverage and ~116 MW MAE are consistent with this. Suggested values:

optimizer = torch.optim.Adam(model.parameters(), lr=1e-4, weight_decay=1e-3)
EPOCHS = 150   # let early stopping with patience=15 decide

MINOR  DIFF_LAG and HORIZON are the same value defined separately

HORIZON  = 24   # line 84  — steps ahead to predict
...
DIFF_LAG = 24   # line 233 — seasonal differencing lag

Both happen to be 24 but are separate variables. If one is changed without the other, the differencing and inversion logic silently breaks. Consider setting DIFF_LAG = HORIZON explicitly.

CORRECT  Wind injection scaling is dimensionally consistent

renew_std = x_std[0, 0, 0, RENEW_IDX].item()    # EE node, raw MW std
x_mod[t, :, 0, RENEW_IDX] += wt / renew_std      # wt in MW → normalized delta

The scaler computes per-node, per-feature statistics (std(dim=(0,1), keepdim=True) preserves N and F dimensions), so renew_std is the true EE-node renewable std in MW. Dividing raw MW delta by raw MW std gives the correct normalized delta. ✓

CORRECT  Quantile loss (pinball loss) is correctly implemented

e = targets - preds[:, i]
losses.append(torch.max(q * e, (q - 1) * e))

Standard pinball loss: when under-predicting (e > 0), loss = q × e; when over-predicting (e < 0), loss = (1-q) × |e|. Correct. ✓

CORRECT  Differencing and inversion logic is correct

y_diff  = y[DIFF_LAG:] - y[:-DIFF_LAG]   # 24 h seasonal difference
y_last  = y[:-DIFF_LAG]                   # level 24 h before target
# inversion: result = diff_pred * y_std + y_mean + y_last

The PowerScaler.inverse_y() correctly recovers the absolute level. y_last_test[i] correctly indexes the level 24 h before each test target. ✓

CORRECT  Wind injection temporal padding is correct

_pad = np.zeros(SEQ_LEN)   # 48 zeros for Dec 30–31 input windows
wind_scenA = np.concatenate([_pad, (scenA - baseline).values])

Prepending SEQ_LEN=48 zeros ensures the input windows that include December get zero wind injection. Without this, Jan 1 wind would be incorrectly injected into Dec 30-31 sequence positions. ✓

MINOR  Double attention in STGNN is redundant and unscaled

GATv2 already computes attention-weighted neighbour aggregation. Then a second attention is applied for the GRU input:

attn_weights = torch.softmax(
    torch.matmul(ee_seq.unsqueeze(2), neigh_features.transpose(-1, -2)), dim=-1)
neigh_seq = torch.matmul(attn_weights, neigh_features).squeeze(2)

The dot-product attention here is not scaled by sqrt(d_k) as in standard scaled dot-product attention, which can cause softmax saturation with larger hidden dimensions. Not a correctness error, but redundant with GATv2 and slightly fragile.

2. SARIMAX Demand Model (Timeseries.ipynb)

MODERATE  get_forecast() uses the wrong year's initial model state

year = rng.choice(years)          # e.g. picks 2021
fit  = fitted_models[year]
forecast = fit.get_forecast(
    steps=len(X_future), exog=X_future   # X_future = Jan 2026 weather
).predicted_mean

get_forecast() continues from the AR/MA state at the end of the model's training period — i.e., from January 31 of the randomly chosen year (e.g. 2021). But X_future is January 2026 weather. The autoregressive state is from the wrong year, creating an initial-condition mismatch for the first ~24 hours of each simulation. The seasonal differencing (D=1, s=24) partially mitigates this, but the correct approach would be to apply the model to December 2025 data first to properly initialize the state. In practice, the bias likely washes out after the first day and results are still reasonable.

MINOR  Residual noise is iid Gaussian, not time-correlated

sigma = resid.std()
noise = rng.normal(loc=0, scale=sigma, size=len(X_future))

Real SARIMAX residuals have remaining autocorrelation (visible in the ACF plots in the notebook). Drawing iid noise treats each hour as independent, which slightly underestimates uncertainty in adjacent hours. The MC confidence band is therefore slightly too narrow. Bootstrapping residual blocks would be more accurate but is a minor issue for a first-order analysis.

CORRECT  Beta adjustment logic is mathematically correct

beta_adjustment += (beta_draw - beta_original) * X_future[feature].values

Since forecast already includes beta_original × X_future, adding (beta_draw - beta_original) × X_future correctly replaces the original coefficient with the drawn one. Net effective beta = beta_draw. ✓

CORRECT  SARIMAX model selection and exog specification

SARIMAX(2,0,2)(1,1,2,24) selected by AIC across all candidate orders fitted on each year separately. Exogenous variables (24h rolling temperature, wind speed, weekend flag) are appropriate seasonal demand drivers. The 2026 exog data correctly uses actual January 2026 weather from ERA5 reanalysis. ✓
